## 2026-10-01 파일 끌어서 카드 열기

### 목표
- 탐색기(Win+E)에서 파일을 집고 카드에 올리면 흰 선이 2초 동안 차오르고, 다 차면 카드 창이 열려 그 앱에 파일을 놓을 수 있음

### 문제와 원인
- 파일을 끌고 카드에 올려도 아무 반응이 없었음
- 원인: 끌기(OLE 드래그) 중에는 마우스를 탐색기가 붙잡고 있어 사이드바에 마우스 이동(`WM_MOUSEMOVE`)이 오지 않음. 사이드바가 드롭 대상으로 등록되지 않아 끌기 위치를 알 방법이 없었음

### 구현
- 사이드바 창을 드롭 대상(`RegisterDragDrop`, `OleInitialize`)으로 등록. 드롭은 받지 않고(효과 "없음") 끌기 위치만 받음 → 파일이 실수로 사이드바에 떨어지지 않음
- 카드 위에 올라가면 마우스 호버와 같이 카드가 정면으로 커지고, 흰 선이 윗변 가운데에서 양쪽으로 2초 동안 차오름(카운트다운). 다 차면 그 창을 엶(`SwitchTo`)
- 호버 선 설정을 꺼 두어도 카운트다운 선은 표시 (무엇이 곧 일어나는지 알려 주므로)

### 엣지 케이스
| 경우 | 처리 |
|---|---|
| 2초 전에 카드에서 벗어남 / Esc로 끌기 취소 / 다른 곳에 놓음 | 타이머와 선 취소, 사이드바가 접혀 있었으면 다시 접힘 |
| 다른 카드로 옮김 | 그 카드에서 2초 다시 셈 |
| 카드가 열린 뒤 커서가 아직 사이드바 위 (다른 카드가 그 자리로 옴) | 커서가 카드 밖으로 나갈 때까지 다시 열지 않음 (연속으로 열리지 않게) |
| 사이드바가 접혀 있음 | 화면 끝에 끌고 가면 나옴 |
| 2초가 됐을 때 다른 전환 중 / 메뉴·설정이 열려 있음 | 끝날 때까지 100ms마다 다시 확인 |
| 카드의 창이 그사이 닫힘 | 열지 않음 |
| 창을 앞으로 가져올 때 | 끌기 중에는 가짜 Alt 키 입력을 쓰지 않음 (Alt가 드롭 동작을 "바로 가기 만들기"로 바꿀 수 있음) |

### 확인
- 빌드 성공, 드롭 대상 등록 확인(trace `drop target registered`)
- 사용자 실사용 3회: 카드 위 2.0초 뒤 열림, 창은 그 뒤 109ms에 앞으로. 2초 전에 다른 카드로 옮기면 열리지 않고 새 카드에서 다시 셈
- 열린 앱에 실제로 파일이 들어갔는지는 trace로 알 수 없어 미확인

## 2026-10-01 테두리 빛 색 설정

### 목표
- 카드 테두리 애니메이션 색을 설정에서 고를 수 있게. 마우스 올리기 / 파일 올리기 / 새 알림 테두리는 모두 같은 색

### 구현
- 설정 > 모양 > **테두리 빛 색**: 흰색(기본), 주황, 파랑, 초록, 보라, 분홍 색 견본 6개. 고른 견본에 고리 표시
- 저장: `HKCU\Software\StageManager\Settings\TraceColor` (0~5, 범위 밖이면 보정)
- 세 애니메이션이 같은 브러시 묶음을 쓰고, 색을 바꾸면 브러시 색만 바꿔서 이미 돌고 있는 선(알림 반복 선 포함)도 바로 바뀜. 새로 만드는 것이 없어 추가 자원 없음
- 알림의 주황 점은 애니메이션이 아니라서 그대로 주황

### 바뀐 점
- 이전에는 알림 테두리가 항상 주황, 호버는 흰색이었음. 이제 둘 다 고른 색 (기본 흰색)

## 2026-10-01 테두리 빛 굵기 설정

### 문제와 원인
- 테두리 빛이 너무 얇아 잘 안 보임. 원인: 굵기가 1px로 고정(카드 확대 비율로 나눠 화면에서 1px)

### 구현
- 설정 > 모양 > **테두리 빛 굵기**: 1~5px 단계 조절, 기본 2px (화면 DPI에 맞춰 커짐)
- 저장: `HKCU\Software\StageManager\Settings\TraceWidth` (범위 밖이면 보정)
- 호버·파일 올리기·알림 테두리 모두 같은 굵기. 바꾸면 돌고 있는 알림 테두리도 새 굵기로 다시 그림
- 파일 올리기 카운트다운은 전에 1.5배였던 것을 같은 굵기로 맞춤
- 굵어도 선은 카드 안쪽에 그려져 카드 밖으로 삐져나가지 않음

## 2026-10-01 테두리 빛 "앱 색"

### 목표
- 테두리 빛 색 견본에 하나 추가: 카드마다 그 앱 로고의 대표색, 채도를 조금 높여 잘 보이게

### 구현
- 설정 > 모양 > 테두리 빛 색의 마지막 무지개 견본 = 앱 색 (`TraceColor` = 6)
- 대표색: 카드 아이콘용으로 이미 읽어 둔 128px 아이콘에서, 색이 있는 픽셀(채도 0.3 이상, 밝기 0.35 이상)을 색상 36칸으로 나눠 가장 많은 색을 고름(여러 색 로고가 탁한 평균색이 되지 않게). 고른 색은 채도 +0.15, 밝기 최소 0.9
- 색 있는 픽셀이 1/12 미만인 흑백 로고(ChatGPT, Notion, 터미널 등)는 흰색
- 앱마다 한 번만 계산해 기억, 그 색을 쓰는 카드가 처음 빛날 때만 계산(앱 색을 안 쓰면 계산 안 함). 터미널은 탭(셸)이 바뀌면 다시 계산

### 확인
- 실행 중인 앱 아이콘으로 같은 계산 시험: Claude #E65E31, Spotify #00E652, Discord #3241F6, Obsidian #763EE6, Chrome #FABB00, ChatGPT·Notion·Terminal·Zed 흰색
- 첫 시험에서 ChatGPT(검정 로고)가 연보라로 나오고 Discord가 너무 진한 파랑이 됨 → 색 있는 픽셀 기준을 높이고 채도 올림을 줄여 해결
- 대기 자원: CPU 0.14%, RAM 6.1MB, GPU 0.02% (기준 1% 미만)

## 2026-10-01 카드 순서 옮기기, 폴더로 묶기, Alt+1~9

### 목표 (사용자 결정)
- 카드를 다른 카드 위에 놓으면 그 자리로 가고 원래 카드는 밀림. 옮긴 순서는 유지(새로 내려간 창만 맨 위)
- 카드를 다른 카드 위에 들고 있으면 테두리 빛이 차오르고, 다 차면 폴더로 묶임(2×2: 1 2 / 3 4)
- 폴더 클릭 또는 Alt+숫자: 펼쳐서 고르기. 펼친 상태에서 Alt+숫자는 폴더 안 창
- 카드 수 설정(예: 6)은 그대로, 폴더는 1장. Alt+1~9(카드 수 최대 9로)
- 폴더 빼기: 펼친 폴더에서 끌어내기

### 구현
- 폴더(`CardFolder`)는 창 목록(최대 4개)과 폴더 카드 하나. 묶인 창의 카드는 기존 목록(`m_cards`)에 그대로 두고, 사이드바만 그 자리에 폴더 카드 1장을 보여 줌 → 닫힌 창 정리, 알림, 소리, 데스크톱 전환 같은 기존 처리는 그대로 동작
- 창 기준(HWND)으로 기억해서, 창이 가운데에 나갔다 와서 카드가 새로 만들어져도 같은 폴더로 돌아옴
- 폴더 카드: 4칸 격자에 각 창의 사진(창 자신의 브러시를 같이 써서 새 사진이 바로 반영)과 앱 아이콘. 회색/유리 카드 모양 설정을 따름
- 알림 점·스피커: 폴더 안 창 중 하나라도 있으면 폴더에 표시. 폴더의 스피커를 누르면 소리 나는 창 모두 음소거/해제
- 손으로 옮긴 뒤에는 가운데에 갔다 돌아오는 카드가 원래 자리로 돌아감. 폴더 창은 폴더 옆으로
- 폴더 창이 최소화되거나 다른 창으로 바뀌면 폴더 카드 자리로 날아 들어감
- 카드 수 설정 1~9장, 단축키는 카드 수만큼만 등록(다른 앱의 Alt+숫자를 필요 이상 가져가지 않음)

### 엣지 케이스
| 경우 | 처리 |
|---|---|
| 폴더 창이 닫힘 / 앱 제외 / 고정 | 폴더에서 빠짐. 1개만 남으면 폴더가 풀림 |
| 고정 카드 | 묶지 않음(고정 카드는 맨 위 자기 순서 유지). 고정 카드끼리는 기존처럼 순서만 바뀜 |
| 폴더를 폴더에, 꽉 찬 폴더(4개)에 | 묶지 않음(테두리 빛도 안 나옴) |
| 폴더를 화면 가운데로 끌어 놓음 | 열지 않고 제자리로 돌아감 |
| 펼친 폴더에서 마우스가 사이드바를 벗어남 / 빈 곳 클릭 / 다른 창이 앞으로 옴 | 폴더가 닫힘. 단축키로 펼친 경우 6초 뒤 닫힘 |
| 파일을 끌고 폴더 위에 2초 | 폴더가 펼쳐지고, 안의 창 위에 2초 더 들고 있으면 그 창이 열림 |
| 전환 중 폴더 클릭 | 끝난 뒤 실행(대기열이 창 대신 카드를 기억하도록 바꿈) |
| 묶기 직후 | 마우스 버튼을 아직 누르고 있어도 끌기가 끝나고 카드가 폴더로 들어감 |
| 이름 충돌 | Windows 셸에 `Folder` 형식이 있어 `CardFolder`로 이름 지음 |

### 확인
- 빌드 성공(경고 없음), 배포 후 실행 유지
- 실제 끌기·묶기는 마우스 입력이 필요해 사용자 시험 대기 (trace: `grouped into a folder`, `card moved`, `folder opened`)
- 폴더는 재시작하면 풀림(재시작 후 유지는 선택하지 않음)

## 2026-10-01 폴더 고정, 펼치기/닫기 애니메이션, 폴더 안 창 번호

### 요청과 구현
| 요청 | 구현 |
|---|---|
| 폴더 고정, 고정해도 순서 이동 | 폴더 우클릭 → 폴더 고정 / 고정 해제. 고정 카드 목록에 `folder#<번호>`로 들어가 고정 카드와 함께 맨 위, 끌어 놓으면 기존 고정 카드처럼 자리 바꿈. 폴더는 세션 동안만 있으므로 이 항목은 저장하지 않음. 고정 폴더에도 창을 더 묶을 수 있음 |
| 펼치기/닫기 애니메이션(클릭·단축키 모두) | 펼칠 때: 폴더 카드 자리에서 작고 흐린 카드들이 제자리로 커지며 나옴. 닫을 때: 카드들이 폴더 카드로 줄어들며 들어가고 폴더 카드가 다시 나타남. 펼친 폴더에서 창을 고르면 나머지 카드도 폴더로 들어감. 폴더 풀기도 같은 펼침 |
| 폴더 안 1을 켠 상태에서 Alt+폴더 번호 시 애니메이션 없음 | 단축키가 폴더를 펼치는 대신 폴더 안 창을 바로 열도록 바뀌어, 창이 폴더 카드에서 날아 나오는 전환 애니메이션이 나옴 |
| 쓰는 중인 창은 폴더에서 안 보이게, 남은 카드 재정렬 | 가운데에 열린 창은 폴더 그림·펼친 목록·번호에서 빠지고 남은 창이 1, 2... 순서로 당겨짐. 내려오면 다시 폴더에 들어감 |
| 1 / 2 / [3,4] / 5 / 6 에서 Alt+3=폴더 안 3, Alt+4=폴더 안 4 | 단축키 번호는 폴더 안 창을 하나씩 셈. 등록 개수 = max(카드 수 설정, 실제 번호 수), 최대 9. 사이드바가 바뀔 때 필요한 만큼만 다시 등록 |

### GPU 메모리 증가 (기존 문제, 미해결)
- 증상: 창 사진을 찍을 때마다(전환 1번에 1~2장) 전용 GPU 메모리가 정확히 12.0MB씩 늘고 줄지 않음. 30분 사용에 900MB 이상
- 오늘 변경 때문인지 확인: 어제 버전(fb6934d)을 따로 빌드해 같은 방식으로 2.5분 측정 → 똑같이 12MB씩 증가(93 → 439MB). 오늘 작업이 원인 아님
- 시도 3번(규칙상 최대), 모두 효과 없어 되돌림
  1. 사진 후 D3D 명령 비우기(`Flush`)
  2. Direct2D 텍스처 캐시 상한 24MB + 사진마다 비우기
  3. 사진마다 `CompositionGraphicsDevice.Trim()` + `IDXGIDevice3::Trim()`
- 원인 후보
  - 12.0MB = 2048×1536×4로 크기가 늘 같음 → 창 크기와 무관한 고정 크기 할당. 컴포지션 그림판(아틀라스) 페이지, 또는 캡처 프레임 풀이 쓰는 공유 텍스처일 가능성
  - 캡처는 매번 새 작업 스레드(MTA)에서 프레임 풀·세션을 만들고 닫음. 스레드별로 남는 자원이 있을 수 있음
- 다른 해결 방법
  - 캡처 장치·프레임 풀을 하나 만들어 계속 재사용(매번 새로 만들지 않기)
  - 사진을 `CompositionDrawingSurface` 대신 D3D 텍스처 + `CompositionSwapChain`/공유 표면으로 직접 관리
  - 일정량(예: 200MB)을 넘으면 사진용 장치를 새로 만들어 통째로 비우기(`Recover`와 같은 경로)
  - PIX/GPUView로 이 12MB 할당의 출처 확인

## 2026-10-01 고정 = 자리 고정

- 사용자 정의: 고정은 카드 위치를 고정하는 것. 그 창을 불러오면 카드도 빠져야 함
- 이전: 고정 카드는 그 창이 가운데에 떠 있어도 사이드바에 계속 남아 있었음
- 변경: 고정 카드는 목록에서 자리를 그대로 지키되, 창이 가운데(무대)에 있는 동안은 사이드바에 표시하지 않고 칸도 차지하지 않음. 창을 내리거나 다른 창으로 바꾸면 고정 자리로 날아 돌아옴. 단축키 번호도 보이는 카드 기준(빠진 동안은 번호 없음)

## 2026-10-06 상태 맞추기(Reconcile): 알림을 놓쳐도 사이드바가 실제 창과 어긋나지 않게

### 같은 종류의 문제 (데스크톱 전환 건과 같은 원인: 한 가지 알림에만 의존)
| 경우 | 전에는 |
|---|---|
| 앱이 포커스 없이 창을 다시 띄움(알림 클릭 등) | 화면에 떠 있는데 카드가 남음 |
| 최소화·숨김 알림을 놓침 | 사라진 창이 "무대"에 남음 |
| 창이 처음부터 최소화된 채 열림 | 카드가 안 생김 |
| 데스크톱 전환 뒤 앞 창 변경 없음 | 클릭 전까지 이전 데스크톱 카드 (앞 항목에서 수정) |

### 구현
- `Reconcile()`: 사이드바가 믿는 상태와 실제 창을 비교해 바로잡음
  - 다른 데스크톱이면 `SyncDesktop`
  - 무대 창이 최소화됐거나 셸이 숨김(다른 데스크톱으로 이동) → 카드로
  - 무대 창이 숨겨졌거나 앱이 스스로 숨김(스토어 앱 닫힘) → 기존 숨김 처리(닫힘/트레이 판단)
  - 카드의 창이 이 모니터에 다시 떠 있으면 → 무대로
  - 최소화돼 있는데 카드가 없는 창 → 카드 만들기
- 폴링 없음. 이런 일을 알리는 알림이 올 때만, 30ms 모아서 한 번(최대 100ms 안에는 반드시) 실행: 최소화 해제(`MINIMIZEEND`, 새로 연결), 클로킹 변경(관리하는 창만), 전환 직후 재확인
- 전환 애니메이션 중이면 끝날 때 실행

### QA (검토 에이전트 + 실사용)
| 찾은 문제 | 수정 |
|---|---|
| 새 데스크톱의 창들이 카드가 되는 중(사진 찍은 뒤 최소화) "다시 떴다"로 오인해 모두 무대로 | 사진 찍는 중인 카드(`adopting`)는 제외 |
| 애니메이션 중 방금 나간 창 카드를 누르거나 Alt+숫자 → 그 창이 최소화됨 | 끊을 때 고른 창은 내리지 않음(`keep`), 단축키 대상은 끊기 전에 결정 |
| 들어오던 창이 아직 안 떴을 때 다른 전환 → 두 창이 함께 남음 | 바로 다음 전환이 있으면 들어오던 창을 띄우지 않음 |

| 시작 메뉴·검색 등 모든 클로킹에 반응 / 애니메이션 중 33Hz로 재시도 | 관리하는 창만, 애니메이션 중에는 끝날 때 한 번 |
| (실사용) 설정 앱을 닫을 때 0.4초 동안 카드가 깜빡 생김 | 앱이 스스로 숨긴 경우는 "다른 데스크톱"이 아니라 숨김으로 처리 |
| (실사용) 최소화가 늦게 끝나는 앱(WinForms)을 다시 무대로 끌어옴 | 사이드바에 막 들어온 카드는 1.5초 뒤 다시 확인 |

## 2026-10-07 네 손가락으로 데스크톱을 옮기면 떠 있던 창이 내려감

### 원인 (trace에 "we minimize"(우리가 내린 창) 기록을 추가해 찾음)
| 경우 | 무슨 일이 있었나 |
|---|---|
| 빠르게 여러 데스크톱을 넘김 | Windows가 "현재 데스크톱"을 바꾸기 전에 새 데스크톱 창(Orca)을 앞으로 보냄 → 같은 데스크톱 안의 전환으로 오인해 이전 데스크톱 창(Obsidian)을 내보내는 전환 시작 → 다음 넘김이 그 전환을 끊으며 Obsidian을 최소화 |

| 단축키를 빠르게 연달아 누름 | 끊긴 이전 전환의 최소화 명령(비동기)이 늦게 도착해 방금 고른 창을 내림 |

### 수정
- 앞으로 온 창의 데스크톱을 직접 확인(`DesktopMovedTo`): 다른 데스크톱 창이면 Windows의 현재 데스크톱이 아직 안 바뀌었어도 데스크톱 전환으로 처리

- 데스크톱을 맞출 때(`SyncDesktop`) 그 데스크톱에 떠 있는 창은 모두 무대로 유지, 최소화된 창만 카드로
- 우리가 내린 창을 기억해(`m_selfMinimized`), 그 최소화가 늦게 도착했을 때 이미 다시 고른 창이면 즉시 되돌림
- trace: `we minimize`(우리가 내림), `minimize (not on stage)`, `stale minimize ... undone`, `another desktop: transition cut short`

- 넘김 직후 Windows가 직접 창을 최소화한 사례 1건(우리 기록 없음): 대각선으로 밀면 "네 손가락 아래로 = 창 최소화" 제스처로도 인식될 수 있음. 앱에서 막을 수 없음

### 구현
| 기능 | 내용 |
|---|---|
| 1. 폴더 이름 | 폴더 우클릭 → 이름 바꾸기: 카드 위에 입력 상자(Win32 EDIT, 한글 입력). Enter·다른 곳 클릭 저장, Esc 취소, 앞뒤 공백 제거, 최대 30자. 카드 아래쪽 가장자리 가운데에 이름표(기울기·호버·미끄러짐을 따라감, 길면 말줄임) |
